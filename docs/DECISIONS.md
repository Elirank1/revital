## D-007 (integrations) · 2026-07-31 · Outreach composer: normalization scope, BiDi policy, hash choice, null-not-throw
Five autonomous calls inside `src/lib/outreach/**`. (1) Phone normalization is Israel-first but not Israel-only: beyond the charter's 05x matrix it accepts landlines (0X-XXXXXXX), 00/+ international prefixes, the common `972 0XX` stray-zero mistake, bare 9-digit mobiles missing the leading 0, and non-IL E.164 numbers — her contact list will contain all of these; anything ambiguous or malformed returns `null` (compose fails, nothing logged, no throw for the UI to handle). (2) BiDi policy: direction OVERRIDE/EMBED/ISOLATE controls (U+202A–E, U+2066–69) are stripped from outgoing message text (spoofing vector, the charter's "no direction-mark injection"), while plain LRM/RLM are preserved in messages (legitimately used in Hebrew text with numbers) but stripped from phone input where RTL UIs leak them. (3) `hashMessage` is FNV-1a 32-bit over UTF-8 bytes, 8 hex chars — deterministic, dependency-free, verified against standard test vectors; it hashes the sanitized text so the stored hash always equals the message actually placed in the href. (4) `composeAndLog` takes an injectable `now` clock (defaults `Date.now`) for deterministic tests, returns the href for the UI to render as an `<a>`, and logs only on successful composition. (5) Email hash input is `subject\nbody` joined over defined parts. G4 verified: no `window.open`/`location`/`fetch` anywhere in the module (grep clean); tests assert hrefs as inert strings in bare node.

## D-008 (agents-engine) · 2026-07-31 · Spend-cap semantics: UTC day buckets, allow-at-limit, fail-open marker, additive response fields
Wave-0 spend guard (`api/_lib/spend.ts`) counts INCR-then-compare: a call is allowed while `count <= limit`, so call N under limit N succeeds and N+1 gets the 429 — simplest boundary that never wastes a paid call on the block itself. Day buckets are UTC (`toISOString` slice) so serverless regions agree on "today"; TTL 48h self-cleans keys across the boundary. Limits come from `SPEND_CAP_CLAUDE`/`SPEND_CAP_ENRICH`/`SPEND_CAP_GEMINI` with defaults 200/40/40; invalid or non-positive env values fall back to defaults rather than disabling the cap. On Redis failure or missing `KV_REST_API_URL`/`KV_REST_API_TOKEN` the guard fails OPEN (charter mandate) and the handlers surface `spendGuard:'unavailable'` as an additive field on their success JSON (including the Anthropic passthrough in `api/analyze.ts` — clients ignore unknown top-level fields, so flag-off behavior stays byte-identical whenever Redis is healthy). 429 bodies carry an English `error`, a Hebrew `message`, and a `spend:{service,count,limit}` object. The spend key uses the access code verbatim (matches the existing `revital:data:${code}` pattern); empty code buckets as `default`, same as `api/data.ts`.

## D-009 (agents-engine) · 2026-07-31 · Cron auth accepts Vercel Bearer convention and fails closed; audit types local pending pipeline.ts
