# Wave 3 — Bench + Inbox (final build wave; task batches per role)

Plan §6 Wave 3. Binding additions to the Wave-2 contract:

**Bench Sourcer contract:** nightly tick pass + on-new-JD trigger. Matching is Claude-over-JSON through the SAME server-side path as `/api/analyze` (env key), spend-capped via `checkAndCount(code,'claude')` — the ONLY LLM allowed in the tick, incremental (new/changed persons + open mandates since last cursor), batched few-at-a-time within budgetMs. Precision throttle: if accept-rate of its suggestions < 1/5 (from suggestion statuses in the blob), next run's volume auto-drops (halves, floor 1). Output: `bench_match` Suggestions with "why matched" evidence citing person fields; NEVER creates deals directly.
**Deletion cascade contract (platform-data):** `deletePersonCascade(personId, {confirm:true})` → tombstones the Person, its deals, its suggestions, filters its contacts/events, purges bench entry — client path; plus retention setting (months, default off) surfaced in a data panel; export-before-delete offered in UI.
**acceptSuggestion absorption:** `acceptSuggestion(id, opts?: { editedBody?: string })` — absorbs the acceptDraft.ts pre-patch (kanban-ui deletes the helper, two call sites re-point).
**Cron wrapper (agents-engine):** `api/agents/cron.ts` — GET-accepting, same guards (CRON_SECRET fail-closed + preview), internally invokes the tick logic with `codes` from `TICK_CODES`, so a `vercel.json` crons entry becomes possible at G1 (adding the crons entry itself is G1 — do NOT edit vercel.json).
**Morning digest:** deterministic client-side view (not email — cut list): "מה מחכה לך הבוקר" — pending suggestions grouped by agent + top-3 Pit Boss + overdue feedback; one tap into the Approvals Inbox.
